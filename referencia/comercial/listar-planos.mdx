---
title: "Listar planos"
description: "Devolve, em páginas, os planos do seu parceiro, com preço, ciclo, quantidade de Tags e a lista do que cada plano inclui."
api: "GET /api/b2b/v1/plans"
---

Esta chamada devolve o catálogo de planos que o seu parceiro vende. Um plano define quanto o cliente paga a cada ciclo, quantas Tags uma assinatura pode cobrir, de quem é o aparelho enquanto a assinatura existir, se o plano inclui seguro e a lista de recursos que você mostra ao cliente na hora da escolha. O `id` do plano é o `plan_id` que [Criar assinatura](/referencia/comercial/criar-assinatura) pede.

A chamada só lê. Esta API não cria, altera nem arquiva plano, e não existe consulta de um plano pelo `id`: para achar um plano, liste e filtre. Quem cadastra e muda planos é a ClubTrack.

## Quando usar

- Montar a tela em que o cliente compara e escolhe o plano antes da assinatura.
- Descobrir o `plan_id` e conferir o `tag_quota` antes de montar a assinatura: ela não aceita mais Tags do que o plano permite.
- Conferir o preço atual do catálogo. O preço que cada assinatura de fato cobra fica gravado nela, em `price_cents` de [Consultar assinatura](/referencia/comercial/consultar-assinatura), e não muda quando o plano é reajustado.

## Autenticação e permissões

Aceita chave de API ou login humano. Qualquer usuário da equipe do parceiro pode consultar. Parceiro suspenso ou inativo recebe 403. Com chave de API, a lista é a do parceiro dono da chave; com login humano, a da filial ativa. A matriz e as filiais não se misturam: cada uma vê só os planos cadastrados para ela, e plano de outro parceiro nunca aparece. O guia de [autenticação](/guias/autenticacao) explica as duas formas e como escolher a filial quando o usuário tem mais de uma.

## Parâmetros

### Cabeçalhos

<ParamField header="X-Api-Key" type="string" required>
  Sua chave de API, no formato `ttk_` seguido de 40 caracteres. Você pode enviá-la também como
  `Authorization: Bearer <chave>`. Se estiver chamando com o token de um usuário da equipe, envie só o `Authorization`.
</ParamField>

<ParamField header="X-Partner-Branch-Id" type="string (UUID)">
  Filial em nome da qual o usuário está consultando. Só tem efeito no login humano, e só é obrigatório quando o usuário
  pertence a mais de uma filial. Com chave de API, o cabeçalho é ignorado.
</ParamField>

### Consulta

Os filtros se combinam: cada filtro a mais restringe o resultado. Dentro de um mesmo filtro, separe valores por vírgula para
aceitar qualquer um deles. Mais detalhes em [Paginação, filtros e ordenação](/guias/paginacao-filtros-ordenacao). A chamada não
oferece `include`: a lista de recursos (`features`) já vem em todo plano.

<ParamField query="filter[status]" type="string">
  Situação do plano, comparação exata. Valores: `active` (plano à venda) e `archived` (plano retirado de venda). Aceita os dois separados por vírgula, mas aí o filtro não restringe nada.
  Exemplo: `/api/b2b/v1/plans?filter[status]=active`.
</ParamField>

<ParamField query="filter[billing_cycle]" type="string">
  Ciclo de cobrança do plano, comparação exata. Hoje o único valor existente é `monthly` (cobrança mensal), então o filtro
  não restringe nada. Um valor que não existe não dá erro: a lista volta vazia.
</ParamField>

<ParamField query="filter[active]" type="string">
  Atalho para os planos com `status` igual a `active`. O valor que você envia é ignorado (`filter[active]=1` basta), e não
  existe forma de usar o atalho ao contrário: para ver os arquivados, use `filter[status]=archived`.
</ParamField>

<ParamField query="sort" type="string" default="-created_at">
  Campo de ordenação. Aceita `created_at`, `price_cents` e `name`. Prefixe com `-` para ordem decrescente: `sort=price_cents`
  traz o mais barato primeiro, `sort=-created_at` traz os planos mais novos primeiro. Aceita mais de um campo separado por vírgula.
</ParamField>

<ParamField query="per_page" type="integer" default="25">
  Quantos planos vêm por página. Envie um inteiro positivo. Não há teto no servidor, mas páginas grandes ficam lentas:
  um catálogo costuma caber em uma página.
</ParamField>

<ParamField query="page" type="integer" default="1">
  Número da página, começando em 1. Para percorrer tudo, siga `links.next` em vez de montar o número à mão.
</ParamField>

## Resposta

Status `200`. O corpo traz a lista em `data`, os endereços de navegação em `links` e os totais em `meta`.

<ResponseField name="data" type="object[]">
  Os planos da página. Vem vazio (`[]`) quando nenhum plano atende aos filtros.
</ResponseField>

<ResponseField name="data[].id" type="string (UUID)">
  Identificador do plano. É o valor que você envia como `plan_id` ao criar uma assinatura.
</ResponseField>

<ResponseField name="data[].partner_id" type="string (UUID)">
  Parceiro dono do plano: o parceiro ou a filial em nome de quem você chamou.
</ResponseField>

<ResponseField name="data[].name" type="string">
  Nome do plano, como você pode exibi-lo ao cliente, com até 150 caracteres.
</ResponseField>

<ResponseField name="data[].price_cents" type="integer">
  Preço de cada ciclo, em centavos: `2990` é R$ 29,90. Sempre maior que zero. É o preço atual do catálogo; a assinatura
  grava o valor vigente no dia em que é criada.
</ResponseField>

<ResponseField name="data[].billing_cycle" type="string">
  Ciclo de cobrança. Hoje só existe `monthly`: o cliente paga uma vez por mês.
</ResponseField>

<ResponseField name="data[].status" type="string">
  `active`: o plano está à venda. `archived`: o plano saiu de venda. Ofereça ao cliente só planos `active`.
</ResponseField>

<ResponseField name="data[].tag_quota" type="integer">
  Quantas Tags uma única assinatura deste plano pode cobrir. Criar uma assinatura com mais vínculos do que isso
  é recusado com 422.
</ResponseField>

<ResponseField name="data[].tag_ownership_model" type="string">
  De quem é o aparelho enquanto a assinatura existir. `partner_comodato`: o aparelho é do seu parceiro, que o empresta ao
  cliente, e volta ao estoque dele quando a assinatura termina. `customer_owned`: o cliente comprou o aparelho e não há
  devolução. O aparelho recebe esse valor no momento em que a assinatura é criada.
</ResponseField>

<ResponseField name="data[].includes_insurance" type="boolean">
  `true` quando o plano inclui seguro, `false` quando não inclui. Use para mostrar ao cliente, antes de ele escolher, o que
  está e o que não está no plano.
</ResponseField>

<ResponseField name="data[].features" type="object[]">
  Lista do que o plano oferece, já na ordem de exibição. Sempre presente; vem vazia (`[]`) quando o plano não tem recurso
  cadastrado.
</ResponseField>

<ResponseField name="data[].features[].id" type="string (UUID)">
  Identificador do recurso dentro do plano.
</ResponseField>

<ResponseField name="data[].features[].code" type="string">
  Código curto do recurso, estável, para você reconhecer o recurso no seu sistema (por exemplo, para mostrar um ícone).
</ResponseField>

<ResponseField name="data[].features[].label" type="string">
  Texto do recurso, pronto para exibir ao cliente.
</ResponseField>

<ResponseField name="data[].features[].display_order" type="integer">
  Posição do recurso na lista. A própria resposta já vem ordenada de forma crescente por este número.
</ResponseField>

<ResponseField name="data[].created_at" type="string (data e hora ISO 8601)">
  Quando o plano foi cadastrado, em UTC.
</ResponseField>

<ResponseField name="data[].updated_at" type="string (data e hora ISO 8601)">
  Última alteração do plano, em UTC.
</ResponseField>

<ResponseField name="links" type="object">
  Endereços prontos para navegar: `first`, `last`, `prev` e `next`. Já trazem os filtros e a ordenação da chamada atual.
  `prev` é `null` na primeira página e `next` é `null` na última.
</ResponseField>

<ResponseField name="meta" type="object">
  `current_page`, `last_page`, `per_page`, `from`, `to` e `total` (quantos planos existem com esses filtros, somando todas
  as páginas). `from` e `to` vêm `null` quando a lista está vazia. `meta.links` repete a navegação em formato de botões para
  interfaces; quem integra por código usa o objeto `links`.
</ResponseField>

## Erros

| Status | Quando acontece | O que fazer |
|---|---|---|
| 400 | Você enviou um filtro ou uma ordenação que a rota não aceita. A mensagem lista os nomes aceitos, em inglês. | Corrija o nome do parâmetro. Os nomes diferenciam maiúscula de minúscula e o filtro de ciclo usa sublinhado (`billing_cycle`). |
| 400 | Login humano com usuário que tem mais de uma filial e sem `X-Partner-Branch-Id`. | Envie o cabeçalho com a filial desejada. |
| 401 | Não há chave, a chave é inválida, foi revogada ou expirou. Com login humano: usuário inativo ou token expirado. | Confira a credencial. Revogação leva até 60 segundos para valer. |
| 403 | O parceiro está suspenso ou inativo, ou a filial informada não pertence ao usuário. | Fale com a ClubTrack se o parceiro deveria estar ativo. |
| 429 | Passou de 1000 chamadas por minuto com a chave. | Espere o tempo do cabeçalho `Retry-After` e repita. |

Os status 401, 403 e 429 valem para qualquer chamada. O corpo é sempre `{"message": "..."}`; o guia de [erros](/guias/erros)
traz os textos exatos.

```bash cURL
  --header "Accept: application/json" \
```

```python Python
import os

resposta = requests.get(

        "Accept": "application/json",

    params={
        "filter[status]": "active",
        "sort": "price_cents",
        "per_page": 2,
    },
    timeout=30,
)

planos = resposta.json()
```

```php PHP
use GuzzleHttp\Client;

$http = new Client(['base_uri' => 'https://core.clubtrack.com.br']);

    'headers' => [

    'query' => [
        'filter' => ['status' => 'active'],
        'sort' => 'price_cents',
        'per_page' => 2,
    ],
```

## Detalhes que ajudam

- Plano `archived` continua na lista quando você não filtra. Para montar a tela de escolha, use `filter[status]=active`.
- A chamada de [criar assinatura](/referencia/comercial/criar-assinatura) não confere a situação do plano. A trava de não vender plano
  arquivado é sua: envie só `plan_id` de plano `active`.
- `price_cents` e os demais valores em dinheiro da API trafegam sempre em centavos, como inteiro. A formatação em reais é do seu sistema.
