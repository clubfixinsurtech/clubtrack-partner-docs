---
title: "Consultar o perfil do parceiro"
description: "Devolve o nome, o logo, o tipo (principal ou filial) e o modelo de cobrança do parceiro em nome do qual você está chamando."
api: "GET /api/b2b/v1/partner"
---

Esta chamada devolve o perfil resumido do parceiro da sua credencial: nome, logo, se é o parceiro principal ou uma filial e como ele é cobrado. Você a usa para montar o cabeçalho de uma tela com a marca do parceiro e, principalmente, para ler `billing_model`, que muda o que acontece depois de [criar uma assinatura](/referencia/comercial/criar-assinatura).

Ela mostra só o parceiro dono da chave. Para ver o parceiro principal e todas as filiais, use [Listar o hub e as filiais](/referencia/conta-e-equipe/listar-filiais).

## Quando usar

- Antes de montar o fluxo de venda, para saber se o parceiro é cobrado por assinatura (`per_subscription`) ou de forma consolidada (`consolidated_postpaid`), e então mostrar ou esconder a etapa de pagamento do cliente.
- Para exibir o nome e o logo do parceiro na tela da sua aplicação.
- Para saber se a credencial atual é do parceiro principal (`is_hub`) ou de uma filial.

## Autenticação e permissões

Use a chave de API. Parceiro suspenso recebe 403. O guia de [autenticação](/guias/autenticacao) explica a chave de API.

## Parâmetros

### Cabeçalhos

Toda chamada leva a sua chave de API no cabeçalho `X-Api-Key`, que o campo de testes (Try it) pede no campo de autorização. Também vale enviá-la como `Authorization: Bearer <chave>`. Veja [Autenticação](/guias/autenticacao).

Esta chamada não tem parâmetros de caminho, de consulta nem corpo.

## Resposta

Status `200`. O corpo traz um único objeto em `data`. O perfil é enxuto de propósito e não traz dados de cobrança, comissão nem de integração.

<ResponseField name="data.id" type="string (UUID)">
  Identificador do parceiro da chamada: o do parceiro principal ou o da filial. É o mesmo `id` que [Listar o hub e as filiais](/referencia/conta-e-equipe/listar-filiais) devolve.
</ResponseField>

<ResponseField name="data.name" type="string">
  Nome do parceiro ou da filial, como está cadastrado.
</ResponseField>

<ResponseField name="data.logo_url" type="string">
  Endereço público completo da imagem do logo, que o seu sistema pode usar direto numa tag de imagem. `null` quando nem o parceiro nem o principal têm logo. Uma filial sem logo própria devolve o logo do parceiro principal.
</ResponseField>

<ResponseField name="data.is_hub" type="boolean">
  `true` quando o parceiro da chamada é o principal (o hub); `false` quando é uma filial. Só o principal pode ter logo próprio, então use este campo para decidir se a sua tela oferece o envio de logo.
</ResponseField>

<ResponseField name="data.billing_model" type="string">
  Como o parceiro é cobrado pela ClubTrack. Dois valores:

  - `per_subscription`: o modelo padrão. Cada assinatura nasce `pending`, e o **cliente** paga pela página de pagamento (`checkout_url`) antes de a Tag liberar a posição.
  - `consolidated_postpaid`: cobrança consolidada pós-paga. A assinatura nasce `active` na mesma chamada, o aparelho é ativado na hora e não há cobrança ao cliente. A ClubTrack fatura o parceiro depois, no fechamento do ciclo.

  O modelo é do parceiro e não muda com a chamada. Quem altera o modelo é a equipe da ClubTrack, e a API não tem chamada para isso.
</ResponseField>

## Erros

| Status | Quando acontece | O que fazer |
|---|---|---|
| 401 | Não há chave, a chave é inválida, foi revogada ou expirou. | Confira a credencial. Revogação leva até 60 segundos para valer. |
| 403 | O parceiro está suspenso ou inativo. | Fale com a ClubTrack se o parceiro deveria estar ativo. |
| 429 | Passou de 1000 chamadas por minuto com a chave. | Espere o tempo do cabeçalho `Retry-After` e repita. |

Os status 401, 403 e 429 valem para qualquer chamada. O corpo é sempre `{"message": "..."}`; o guia de [erros](/guias/erros)
traz os textos exatos.

## Exemplos

<RequestExample>

```bash cURL
curl "https://core.clubtrack.com.br/api/b2b/v1/partner" \
  --header "X-Api-Key: $CLUBTRACK_API_KEY" \
  --header "Accept: application/json"
```

```javascript JavaScript
const resposta = await fetch("https://core.clubtrack.com.br/api/b2b/v1/partner", {
  headers: {
    "X-Api-Key": process.env.CLUBTRACK_API_KEY,
    Accept: "application/json",
  },
});

const { data: parceiro } = await resposta.json();
```

```python Python
import os
import requests

resposta = requests.get(
    "https://core.clubtrack.com.br/api/b2b/v1/partner",
    headers={
        "X-Api-Key": os.environ["CLUBTRACK_API_KEY"],
        "Accept": "application/json",
    },
    timeout=30,
)

parceiro = resposta.json()["data"]
```

```php PHP
use GuzzleHttp\Client;

$http = new Client(['base_uri' => 'https://core.clubtrack.com.br']);

$resposta = $http->get('/api/b2b/v1/partner', [
    'headers' => [
        'X-Api-Key' => getenv('CLUBTRACK_API_KEY'),
        'Accept' => 'application/json',
    ],
]);

$parceiro = json_decode((string) $resposta->getBody(), true)['data'];
```

## Detalhes que ajudam

- Uma filial devolve o `name` e o `id` dela, o `billing_model` dela e o `logo_url` do parceiro principal quando não tem logo próprio.
- O endereço de `logo_url` muda quando o logo é trocado. Não guarde o endereço por tempo indeterminado: leia de novo ao montar a tela.
- Para saber como o parceiro é cobrado, leia `billing_model` uma vez ao iniciar a sessão e guarde. Ele só muda por ação da equipe da ClubTrack.
